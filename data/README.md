# Fusion training corpus, v5

One corpus trains the released pair. Stage 1 fine-tunes the 7B reader on it, stage 2 fine-tunes the
32B query LM on it with the reader frozen and the fusion weight fixed at the value the arm is
evaluated at. It holds 7,280 rows and 133 MB, of which 96% is the `context` field.

## What is released here

| File | Rows | Size | Contents |
|---|---|---|---|
| `binding_corpus_v5.supervision.jsonl` | 7,280 | 6.0 MB | Every row, every field except `context`, plus `context_chars` |
| `binding_corpus_v5_sample.jsonl` | 200 | 3.6 MB | Whole rows including `context`, stratified over the families below, seed 0 |

`scripts/make_release_corpus.py` cuts both files out of the full corpus.

## Fields

| Field | Meaning |
|---|---|
| `example_id` | Family prefix and, for the replay family, the upstream dataset's own id |
| `context` | The text the reader branch sees. The query LM never receives it |
| `question` | The text both branches see |
| `gold` | The dataset's answer where one exists. It is not used as a training target |
| `target` | The teacher's own output, and the only supervision. The 32B teacher generated it with the full context |
| `teacher_text` | The teacher's raw generation before the harness trimmed it |
| `instruction` | Name of the instruction constant in `src/qa_prompts.py` that built the prompt |
| `meta.fmt`, `meta.source` | Family, and upstream dataset for the replay family |
| `hit_max_new` | Whether the teacher's generation reached the token limit |

## Families, and how a context is rebuilt

| Family | Rows | Context | Where the context comes from |
|---|---|---|---|
| Synthetic dialogue, `v4d-bindv2-*` | 2,971 | 42.6 MB | `gen_binding_corpus_v2.py`, seeded |
| Synthetic journal, meeting, doc, email, `v4-v3-*` | 2,309 | 3.5 MB | `gen_binding_corpus_v3.py`, seeded |
| Replay, `v4-replay-*` | 2,000 | 78.9 MB | `build_ft_mix.py` reads public train splits by id, `gen_binding_corpus_v3.py --replay` folds them in |

The three families are merged by `build_binding_corpus_v4.py`, the teacher targets are generated by
`binding_teacher_gen.py` for the synthetic rows and `ft_mix_teacher_gen.py` for the replay rows, and
`run_v5seed777_train.slurm` assembles v5 out of those pieces and runs stage 1. It keeps a row only
when the teacher's generation is non-empty and terminated on its own, and applies no gold filter and
no curation, so the target is the teacher's behaviour as it stands.

The synthetic families are generated text, so no public id points at them and the generator is the
only way back. The replay family carries contexts drawn from public train splits, 1,028 rows from
2WikiMultihopQA, 666 from SciFact, 156 from LongBench `passage_count` and 150 from LongBench
`passage_retrieval_en`. Each of those rows keeps the upstream dataset's id, and `build_ft_mix.py`
rebuilds the context from it by re-running the same retrieval at the same doc number and seed. We
have not checked that a rebuild comes back byte-identical to the released rows.

The `target` column cannot be rebuilt without GPU time, because it is the 32B teacher's own
generation. That is why the supervision view keeps it for all 7,280 rows.

## What is held out

Every benchmark the paper evaluates on is excluded from this corpus by name, listed as `HELD_OUT` in
`scripts/build_ft_mix.py`. HotpotQA, MuSiQue, LooGLE and LoCoMo are all in that set, so none of the
training contexts comes from an evaluation benchmark. HotpotQA was a training source until
2026-07-29 and was removed for exactly this reason.
